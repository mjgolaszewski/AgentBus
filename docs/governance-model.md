# AgentBus governance model

AgentBus uses released BCF 2.3.4 with Standard profile contract v3. Routing,
custody, installation and compatibility claims require executable evidence tied
to the exact candidate; syntax validation alone is insufficient.

AgentBus is a small service, but its behavioral boundaries are consequential.
It accepts untrusted Slack events, applies routing and reply rules, persists an
inbox and independent consumer cursors, holds a shared bearer credential, and
publishes a release consumed by another repository. A syntax-valid tree alone
cannot establish those properties. Standard v3 can bind them to executable
claims, exact subjects, isolated controls, and release evidence without adding
the independent attestation duties of the Regulated profile.

## Authority boundary

The repository keeps ordinary project authority:

- pull requests run candidate-owned preflight and behavioral evidence on fresh
  GitHub-hosted workers;
- `main` is protected by the terminal governance truth check;
- releases are built from an exact protected Git subject;
- Slack credentials and the live inbox never enter CI or release artifacts.

AgentBus does not install BCF's persistent trusted controller, privileged Apps,
recovery lane, release credentials, or self-governance topology. Those features
are optional and do not prove an AgentBus proposition. The project has no
existing requirement that would justify their authority or operating cost.

## Assurance graph

Cheap preflight proves the locally decidable governance, exposure, and semantic
ownership claims before behavioral work fans out. The remaining claims are
grouped by the proposition each producer proves:

- source quality and static typing;
- client behavior and service contract behavior;
- module size, layer and context membership, import direction, operation
  populations, router thinness, and duplication boundaries;
- secret, dependency, SBOM, and vulnerability properties;
- container runtime behavior and deterministic source-release construction.

The installed canonical graph derives the exact claim, producer, negative-control
and test-manifest population for the current subject. Test placement does not
decide claim ownership. Each producer must establish its declared proposition;
passing a convenient subset is not proof of complete acceptance.

Dependency classes bind each claim to its subject, detector, test population,
toolchain, and trust inputs. A candidate invalidates only affected claims and
their declared dependents. Authenticated evidence for an unchanged dependency
closure may be reused. Unknown or ambiguous classification expands work or
rejects at the deterministic boundary; it cannot silently remove proof.

## Operating contract

The normal agent interface is semantic intent plus exact subject identity. BCF
derives preflight, evidence selection, shard assignment, truth evaluation, and
eligibility from the governed graph. Contributors do not choose test roots,
gate order, or evidence to reuse.

Project-owned files remain the authority for AgentBus semantics. BCF owns its
installed runtime, schemas, and generated projections. Upgrades preserve
application contracts and project controls, then reconcile generated bytes to
a fixed point before the exact final subject is proved.
